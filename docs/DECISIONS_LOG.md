# HawkEye / BountyCam - Architectural Decisions Log (ADR)

---

### [D-01] Local-First Zero-Cloud Execution Architecture
* **Status:** Accepted
* **Context:** Surveillance footage contains sensitive personally identifiable information (PII), proprietary warehouse operations, and private residential movements. Cloud streaming of 12-hour video files incurs high bandwidth costs, latency, and data privacy compliance risks.
* **Decision:** All video processing, frame extraction, object detection, tracking, vector embedding, and spatial indexing run 100% locally on the host workstation. Cloud interaction is strictly confined to Stage 4 where only cropped bounding-box images (a few kilobytes) of Top-K candidates are transmitted to Gemini Flash for precision verification.
* **Consequences:** 
  - Complete data sovereignty and zero surveillance footage upload.
  - Operation remains resilient to intermittent or absent internet connectivity.
  - System requires a local GPU (e.g. RTX 4070 or compatible CUDA/CPU fallback).

### [D-02] FAISS Index Architecture & Vector Persistence Schema
* **Status:** Accepted
* **Context:** Rapid retrieval over thousands of tracked objects across multiple camera streams requires low-latency, scalable vector search.
* **Decision:** We use Meta's FAISS (`faiss-cpu` / `faiss-gpu`) storing 768-dimensional float32 vectors generated by SigLIP. The vector index uses `IndexFlatIP` (inner product for normalized cosine similarity) paired with an SQLite/JSON metadata store.
* **Data Schema:**
  - `vector_id`: uint64 primary key matching the FAISS row index.
  - `track_id`: Integer tracking ID assigned by ByteTrack.
  - `camera_id`: String identifier for the camera source (e.g., `CAM-GATE-01`).
  - `timestamp_sec`: Exact floating-point timestamp in the source video.
  - `bbox`: Normalized bounding box `[x1, y1, x2, y2]`.
  - `crop_path`: Filesystem path to the sharpest crop image.
  - `sharpness_score`: Laplacian variance value used for crop selection.
  - `class_name`: Detected object class (`person`, `bicycle`, `motorcycle`, `car`, `backpack`).
* **Consequences:** Provides sub-10ms similarity queries across tens of thousands of objects with immediate retrieval of source video timestamps and bounding boxes.

### [D-03] PyAV Keyframe Demuxing & Motion Wake-Up Burst
* **Status:** Accepted
* **Context:** Standard video decoding (e.g. naive `cv2.VideoCapture`) decodes every single frame (29.97/25 FPS), requiring ~1.3 million frame decodes for a 12-hour video file. 90%+ of CCTV footage contains no significant activity.
* **Decision:** We utilize PyAV to interface directly with FFmpeg demuxing contexts with `stream.codec_context.skip_frame = "NONKEY"`. In keyframe mode, only I-frames (~1 frame every 2 seconds) are inspected. A lightweight 160x90 grayscale difference matrix monitors activity. If pixel difference exceeds 1.0%, the pipeline wakes up and decodes 3.0 seconds at 5–10 FPS to ensure ByteTrack captures complete object trajectories.
* **Consequences:** Reduces video decoding time from hours to minutes, achieving 50x–100x speedups without missing fast-moving targets.

### [D-04] SigLIP Base Patch16-224 Multimodal Embedding Model
* **Status:** Accepted
* **Context:** Multimodal search requires high semantic alignment between natural language descriptions (e.g., *"person with yellow helmet on black scooter"*) and cropped object imagery, as well as visual photo-to-photo similarity search.
* **Decision:** We adopt `google/siglip-base-patch16-224` (Hugging Face Transformers) with Sigmoid loss for multimodal pre-training. SigLIP yields significantly better fine-grained zero-shot classification and attribute alignment than standard OpenAI CLIP ViT-B/32, with an efficient 768-dimensional embedding.
* **Consequences:** Superior matching accuracy on fine-grained clothing colors, accessories, and vehicle attributes with fast inference times on local CUDA hardware.

### [D-05] Decoupled Next.js 14 App Router + FastAPI Backend with Real-Time Telemetry
* **Status:** Accepted
* **Context:** The application requires a Palantir-style dark forensic command center with interactive video scrubbing, canvas drawing for polygon tripwires, interactive Leaflet maps, and live streaming ingestion telemetry.
* **Decision:** 
  - **Frontend:** Next.js 14 (React, TypeScript, Tailwind CSS, Lucide icons, HTML5 Canvas, Leaflet).
  - **Backend:** FastAPI (Python 3.10+, PyAV, Ultralytics YOLOv8, Transformers, PyTorch, FAISS, Shapely).
  - **Communication:** REST API for search/configuration + WebSocket/Server-Sent Events (SSE) for streaming real-time ingestion telemetry (FPS, frame count, discarded percentage, GPU memory usage).
* **Consequences:** Clean separation of concerns, rapid UI responsiveness, real-time forensic feedback, and smooth timeline scrubbing.
